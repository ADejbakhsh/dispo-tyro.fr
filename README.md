# Colmiane — Tyrolienne Availability Tracker

Scrapes real-time reservation/availability data for the **TYROLIENNE** (zip line) activity at [Colmiane](https://colmiane.axess.shop) from the Axess Shop ticketing platform, and displays it as an interactive dashboard.

## Project structure

| File | Purpose |
|---|---|
| `api_client.py` | Python client — fetches data from Axess Shop and exports to JSON |
| `index.html` | Static dashboard — renders the JSON as an interactive chart + upcoming-days strip |
| `data.json` | Exported data (generated by `api_client.py --export`) |

## Quick start

```bash
# Export the next 14 days of time-slot data to data.json
python api_client.py --export

# Export a custom number of days
python api_client.py --export 7

# Run without --export to print a live summary to the terminal
python api_client.py
```

Then open `index.html` in a browser to see the dashboard.

### Preserving today's data across runs

As the day progresses, time slots that have already passed disappear from the Axess Shop server (the Contingent page only returns future slots). To keep a complete picture of the day, `--export` **merges** today's slots with any previous `data.json`:

- Morning slots from an earlier export are preserved
- Afternoon slots are updated with fresh data from the current run
- All other dates use the latest data only (no merge needed)

This means you should run `--export` at least once early in the day (to capture all 12 slots) and can re-run later to update future dates without losing anything.

## Dashboard (`index.html`)

A static HTML page that loads `data.json` and renders:

- **Hero cards** — today and tomorrow with reserved count, percentage, and mini progress bars
- **Line chart** — per-slot reservations for a selected date, with a dashed 16-place capacity reference line
- **Upcoming strip** — 14-day scrollable chip list; click any day to switch the chart
- **Auto-refresh** — re-fetches `data.json` every 4 hours; updates the "il y a X min" timestamp every minute

No build step, no server — just open the file.

## Python API client

### Recommended: from a URL

The URL is the single source of truth — the client parses `ProjNr`, `PoolNr`, and `TicketTypeId` automatically:

```python
from api_client import AxessShopClient

# Create client from the Calendar page URL
client = AxessShopClient.from_url(
    "https://colmiane.axess.shop/fr/Products/Tickets/Calendar/529/63/1122"
)

# All URLs are derived from that one input:
print(client.calendar_url)     # .../Calendar/529/63/1122
print(client.contingent_url)   # .../Contingent/529/63/1122
print(client.calendar_api_url) # .../api/TicketsV4TimeSlotApi/...

# Get daily summary for current month
daily = client.get_daily_availability()
for entry in daily:
    print(f"{entry['date']}: {entry['available']}/{entry['max']} free")

# Get per-slot details for a specific date
slots = client.get_time_slots("2026-07-15")
for s in slots:
    print(f"{s['time']}: {s['available']}/{s['max']} free ({s['reserved']} reserved)")

# Get all upcoming days
upcoming = client.get_all_upcoming_slots(num_days=14)
```

### Alternative: explicit parameters (backward compatible)

```python
client = AxessShopClient(proj_nr=529, pool_nr=63, ticket_type_id=1122)
```

### Output format

Each time slot dict:
```json
{
  "time": "10:00",
  "available": 11,
  "max": 16,
  "reserved": 5
}
```

Each calendar entry:
```json
{
  "date": "2026-07-15",
  "tariff": "35,00",
  "available": 16,
  "max": 16,
  "reserved": 0,
  "limited_threshold": 3,
  "time_slot_group_key": 1005
}
```

## APIs discovered

### 1. `POST /api/TicketsV4TimeSlotApi/GetReservationTimeSlotsForCalendar`
- **Type**: JSON API (XMLHttpRequest)
- **Format**: `application/x-www-form-urlencoded`
- **Purpose**: Returns monthly calendar overview with daily aggregate availability
- **Parameters**: `ProjNr`, `ProductGroupIdentifier`, `Id`, `Month`, `Year`, `CiUppercase`, `SubTypeIdentifiers`, `Type`
- **Auth**: ASP.NET Session cookie only

### 2. `POST /fr/Products/Tickets/Contingent/{ProjNr}/{PoolNr}/{TicketTypeId}`
- **Type**: HTML form submission (full page load)
- **Format**: `application/x-www-form-urlencoded`
- **Purpose**: Returns HTML page with per-time-slot availability data
- **Parameters**: `TicketTypeId`, `ProjNr`, `PoolNr`, `Date`, `PersonTypes[]`
- **Auth**: ASP.NET Session cookie only (session state must be initialized via Calendar page)

## URL pattern

The Axess Shop uses a consistent URL structure:

```
{base_url}/fr/Products/Tickets/Calendar/{ProjNr}/{PoolNr}/{TicketTypeId}
```

The time-slot selection page mirrors it:

```
{base_url}/fr/Products/Tickets/Contingent/{ProjNr}/{PoolNr}/{TicketTypeId}
```

To target a different product or venue, pass the new Calendar URL to `from_url()` — no constants to update.

### Current values (Tyrolienne @ Colmiane)

| Parameter | Value | Notes |
|---|---|---|
| `ProjNr` | 529 | Project identifier |
| `PoolNr` | 63 | Product group / pool |
| `TicketTypeId` | 1122 | Ticket type |
| `SubTypeId` | 1061 | Person type (discovered from page HTML, not in URL) |
| Tariff | 35,00 € | Adult ticket price |

## Authentication

No login required. The site uses:
- `ASP.NET_SessionId` cookie for server-side session state
- `ci=fr` cookie for language preference
- No Bearer tokens, API keys, or OAuth

Session is automatically established by visiting the Calendar page (`_ensure_session()`).

## Activity details

Each operating day has up to **12 time slots of 30 minutes** (10:00–16:00), each with **16 places** — except the 15:00 slot which has **15** (a site quirk, not a bug). The dashboard chart uses a fixed `maxVal = 16` y-axis.

## Caveats

1. **Session-dependent**: The time slot detail page requires server-side session state set by prior page visits. The client handles this automatically by visiting the Calendar page first.
2. **HTML parsing**: Per-slot data is only available in the HTML of the Contingent page (no JSON API). Uses regex with multiple fallback patterns to extract slot data.
3. **Past slots disappear**: As the day progresses, the server stops returning time slots that have already passed. The `--export` command merges with previous `data.json` to preserve them (see "Preserving today's data" above).
4. **No JSON API for time slots**: Per-slot data exists only as an inline JavaScript object in the Contingent page HTML.
5. **Rate limiting**: No rate limiting observed, but be respectful.
6. **Date format**: Dates use `YYYY-MM-DD` format internally. The Contingent POST expects this format.
7. **404 for direct GET**: The Contingent page returns 302 → 404 if accessed via GET without the proper session state.
8. **`SUB_TYPE_ID = 1061`**: This person-type identifier is not encoded in the URL — it's discovered from the page HTML and must be provided separately when using `from_url()`.
